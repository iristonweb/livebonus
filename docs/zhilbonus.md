## Контекст и ценность

**All in Guide** — программа лояльности, которая начисляет баллы за оплату **аренды** или **ЖКУ** через **СБП** (Система быстрых платежей).  
Ключевой принцип: **пользователь платит “как обычно”, но получает выгоду “как в лояльности” — без комиссий и с прозрачными правилами.**

### Для кого

- **Арендаторы и собственники** (регулярные платежи, желание экономить, “платежи без боли”)
- **Жители многоквартирных домов** (ЖКУ, единый кабинет, напоминания/автоплатежи)
- **УК/ТСЖ/арендодатели** (собираемость, цифровизация, удержание жителей, меньше ручной сверки)

# 2. Как это работает

Текстовая “инфографика” (в интерфейсе — 4 карточки/лента):

1. **Добавьте договор/адрес**  
   - аренда: договор + реквизиты получателя  
   - ЖКУ: адрес/лицевой счёт, поставщик/УК  

2. **Оплатите через СБП**  
   - QR / deeplink в банк  
   - итоговая сумма видна до подтверждения  
   - **0 ₽** скрытых комиссий для пользователя  

3. **Получите баллы**  
   - начисление после статуса **успешно** от PSP  
   - отображаем: “ожидается → начислено”  

4. **Обменяйте на подарки/скидки/билеты**  
   - витрина: “рядом”, “популярное”, “для вас”  
   - 2–3 клика до получения сертификата/промокода

**Акценты (на каждом шаге):**
- данные хранятся в РФ (152‑ФЗ)
- согласия управляются (opt‑in/opt‑out)
- прозрачные правила начисления и лимитов

# 3. Баллы и вознаграждения

## Правила начисления (MVP)

| Правило | Значение | Комментарий |
|---|---:|---|
| Начисление | **1% = 1 балл за 100 ₽** | 50 000 ₽ → 500 баллов |
| Лимит | **5 000 баллов/мес** | защита от злоупотреблений |
| Срок жизни | **12 месяцев** | таймер и напоминания |
| Комиссии для пользователя | **0 ₽** | модель монетизации — партнёрская |

## Категории redemption (погашения)

- **Еда и доставка**: Restoclub, Delivery Club, Яндекс.Еда  
- **Транспорт**: Яндекс.Такси, Ситимобил  
- **Путешествия по РФ**: через партнёрский агрегатор (билеты/отели/туры)  
- **Маркетплейсы/ритейл**: Ozon, Wildberries, М.Видео  

> Примечание: в MVP — интеграция через агрегатор офферов/сертификатов, чтобы ускорить запуск и закрыть юридические вопросы по выдаче.

## Пример (в интерфейсе — “калькулятор”)

**Аренда 50 000 ₽ → 500 баллов → сертификат на кофе или скидка на такси**

# 4. Для управляющих компаний и арендодателей

## Выгоды

- **Собираемость ↑**: напоминания, автоплатёж, мотивация баллами
- **Цифровизация**: единый канал платежей/статусов/реестров
- **Лояльность жителей**: “платишь ЖКУ — получаешь выгоду”
- **Снижение нагрузки**: меньше ручной сверки и обращений “где платеж?”

## Как подключиться

1) **API**  
   - статусы платежей  
   - реестры/сверка  
   - привязка лицевых счетов/объектов  
2) **White‑label**  
   - витрина и кабинет под брендом УК  
3) **Интеграторы**  
   - через платформы управления домом (например, Домиленд и аналоги)

## SLA (MVP ориентир)

| Метрика | Цель | Комментарий |
|---|---:|---|
| Подтверждение статуса платежа | до 60 сек | зависит от PSP/банка |
| Уведомления пользователю | до 30 сек | push/SMS/email |
| Реестры/отчёты | ежедневно 06:00 | + on‑demand выгрузки |
| Поддержка B2B | 9×5 / 24×7 (опц.) | по тарифу |

# 5. Безопасность и комплаенс

## Персональные данные (152‑ФЗ)

- хранение и обработка ПДн **на территории РФ**
- минимизация собираемых данных (data minimization)
- раздельные контуры: **профиль / платеж / офферы**
- шифрование “в покое” и “в транзите”, ротация ключей

## Платежи (СБП)

- платежи проходят через **СБП** и **аккредитованных PSP**
- приложение не хранит платежные реквизиты (модель “инициация → подтверждение в банке”)

## AML/KYC (115‑ФЗ)

- AML‑контур (в т.ч. мониторинг/санкции) — на стороне PSP/банка
- продуктовые ограничения/лимиты — как дополнительная защита от фрода

## Rent‑reporting (опционально)

- включается **только по явному согласию** (opt‑in)
- отключается в любой момент (opt‑out)
- логируем изменения согласий (audit trail)

## Логи без PII

- в логах запрещены: ФИО, паспорт, полные адреса, телефоны, email
- допускаются: `user_id`, `account_id`, `payment_id`, статусы, тайминги, коды ошибок
- отдельный защищённый контур для расследований (если требуется)

# 6. Личный кабинет: UX‑потоки

## IA (информационная архитектура)

- **Dashboard**  
  - баланс баллов  
  - ближайший платёж (дата/сумма/статус)  
  - активные офферы рядом  
- **Оплата**  
  - выбор объекта → сумма → СБП → подтверждение  
- **История**  
  - транзакции (платежи)  
  - начисления/списания  
- **Офферы**  
  - категории + поиск + “рядом”  
  - карточка оффера  
- **Настройки**  
  - профиль  
  - согласия (в т.ч. rent‑reporting)  
  - уведомления  

## Поток: оплата (happy path)

1) Пользователь открывает **Оплата**  
2) Выбирает **объект** (адрес/договор/лицевой)  
3) Вводит **сумму**  
4) Видит **итог + сколько баллов начислится + лимиты**  
5) Нажимает **Оплатить через СБП**  
6) Переходит в банк/сканирует QR  
7) Возвращается и видит статус: **Ожидается → Успешно**  
8) Баллы: **начислено** (или “в обработке”)

## Поток: списание на оффер

1) Офферы → выбрать категорию  
2) Открыть карточку → условия  
3) Нажать **Получить** → подтверждение списания  
4) Получить промокод/сертификат + сохранить в “Мои купоны”

## Микрокопирайт (ключевые строки)

- Кнопки: **Оплатить**, **Получить баллы**, **Оплатить через СБП**
- Статусы: **Ожидаем подтверждение банка**, **Платёж успешен**, **Начислили X баллов**
- Безопасность: **Безопасно. Данные в РФ**, **Можно отключить в любой момент**
- Ошибки: **Не получилось подтвердить платёж. Попробуйте ещё раз или выберите другой банк.**

# 7. Техническая спецификация (для dev‑команды)

## Стек (целевой)

- **Web**: Next.js (App Router)  
- **Mobile**: React Native  
- **Backend**: Kotlin + Spring Boot  
- **DB**: PostgreSQL  
- **Cache/Queue**: Redis  
- **Observability**: OpenTelemetry + Grafana/Loki/Tempo (или экв.)

## Архитектура

MVP: **модульный монолит** (единый репозиторий + модули) → Scale: выделение сервисов.

**Модули MVP:**
- `payments` — инициация/статусы/реестры/сверка
- `loyalty` — правила начисления, лимиты, экспирация
- `offers` — каталог офферов, витрина, выдача промокодов
- `profiles` — пользователи, объекты, согласия

Scale: микросервисы  
- **Payments**, **Loyalty**, **Offers** (+ `Reporting` опционально)

## Интеграции

- **СБП через PSP** (например, ЮKassa/иные) — создание платежа, получение статуса, webhooks
- **Geo‑offers** — партнёрский API (каталог/наличие/цены)
- **Автоплатежи** — по готовности UX/регуляторики (и при поддержке PSP/банков)

## Контуры безопасности

- tokenization ПДн (в БД — токены, оригиналы — в защищённом vault/контуре)
- шифрование: TLS in transit, AES‑256 at rest (или сервисные KMS)
- RBAC/ABAC для админки и B2B кабинета
- аудит‑лог для согласий и финансовых операций

## Схема событий (минимум)

```txt
payment.created -> payment.pending -> payment.succeeded|failed
payment.succeeded -> loyalty.credited
loyalty.debited -> offer.redeemed -> voucher.issued
```

## Примеры API (черновик)

```http
POST /api/v1/payments/init
{
  "userId": "u_123",
  "objectId": "obj_987",
  "amountRub": 50000,
  "method": "SBP"
}
```

```http
POST /api/v1/webhooks/psp
# PSP подписывает запрос (HMAC/JWS)
```

```http
GET /api/v1/loyalty/balance?userId=u_123
```

## Нефункциональные требования (MVP)

- p95 API latency: < 400 ms (кроме внешних вызовов)
- RPO/RTO: по договорённости (начать с RPO 15 мин, RTO 2 ч)
- идемпотентность вебхуков PSP
- “exactly once” для начисления баллов (через idempotency keys)

## Дополнение: Регистрация и сценарии объявлений (прототип)

- Тип аккаунта: **Физлицо / Юрлицо**

## Дополнение: Bilt‑style flow и «умные» поля адреса

### Flow «после входа сразу анкета»
- Кнопка **«Войти / Регистрация»** в правом верхнем углу открывает модалку (email → телефон → код).
- После подтверждения контакта пользователь сразу попадает на **/apply** — анкета объявления/поиска без «лишнего шага регистрации».
- Расширенная регистрация (юрданные/согласия/доп. поля) остаётся на **/register** и используется по необходимости (договоры, B2B, документы).

### Умные поля адреса (город / район / метро)
В MVP‑демо реализовано:
- локальные подсказки популярных городов и станций метро (Москва/СПб)
- удалённые подсказки через OpenStreetMap Nominatim (для RU) — как демонстрация UX

В проде рекомендовано:
- провайдер подсказок с SLA и лимитами (DaData/Geo API)
- кэширование, rate‑limit, анти‑абьюз, логирование без PII
