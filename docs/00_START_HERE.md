# All in Guide — AI / Replit Handoff

Версия документации: 2026-08-28  
Источник анализа: архив проекта `allinguide.zip`.

## Что это за проект

All in Guide — русскоязычный frontend-прототип продукта вокруг оплаты жилья/ЖКУ через СБП, начисления баллов и партнёрских привилегий. В текущем репозитории реализован именно UX/UI-прототип на Next.js; полноценного backend/payment/loyalty/CRM контура нет.

Главная цель этих файлов — дать AI-агенту в Replit устойчивый контекст, чтобы он не принимал продуктовый замысел за уже реализованную функциональность.

## Порядок чтения

1. `01_PROJECT_STATUS.md` — фактическое состояние кода.
2. `02_ARCHITECTURE.md` — структура и потоки.
3. `03_PRODUCT_SPEC.md` — продуктовая модель и правила из существующей спецификации.
4. `04_IMPLEMENTATION_PLAN.md` — рекомендуемый порядок превращения прототипа в работающий MVP.
5. `05_TECHNICAL_DECISIONS.md` — зафиксированные инженерные решения и ограничения.
6. `06_RUNBOOK.md` — запуск, проверка и диагностика.
7. `SYSTEM_PROMPT_REPLIT.md` — готовый системный prompt для AI-агента.

## Ключевое правило

Нельзя считать реальными:
- авторизацию;
- SMS;
- платежи через СБП;
- начисление/списание баллов;
- интеграции с банками/PSP;
- передачу данных в БКИ;
- B2B API;
- CRM/webhooks;
- хранение данных на сервере.

Все перечисленное пока находится на уровне UX, product spec или архитектурного замысла.

## Быстрый запуск

```bash
npm install
npm run dev
```

Требование Next.js 16: Node.js >= 20.9.

Текущий `package.json` содержит устаревший для Next.js 16 скрипт:

```json
"lint": "next lint"
```

В Next.js 16 команда `next lint` удалена. Линтер нужно перевести на ESLint CLI или Biome.

## Главные маршруты

- `/` — публичный лендинг.
- `/features` — подробные возможности.
- `/start` — UX-поток оплаты, без реального платежа.
- `/apply` — анкета после demo-auth.
- `/register` — расширенная регистрация и анкета.
- `/partners` — B2B/УК лендинг.
- `/docs` — рендер `docs/all-in-guide.md`.
- `/api/health` — простой health endpoint.

## Самое важное перед дальнейшей разработкой

Перед добавлением новых экранов или API сначала определить, какая часть является:
1. demo/mock;
2. frontend-only;
3. реальной server-side функцией;
4. интеграцией внешнего провайдера.

Не маскировать mock под production.
